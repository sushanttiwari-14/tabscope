## Boundaries and manual reproduction

PDF text highlighting in Chrome's native reader is unavailable; results promise page navigation only. Native jumps reload the reader after committing its fragment, which can reset unsaved annotations. Redirects (even same-host), download-only, POST-only, expired/authentication failures, encrypted/password/copy-restricted, blob/file/internal and over-limit sources have explicit boundaries; fetched GETs do not bypass authentication. A repeatable permitted HTTP(S) source is required. Complex reading order/font encodings can omit text; no OCR/multilingual morphology/full PDF layout reconstruction is claimed. Headers and footers remain searchable. Copy restriction/password/error handling and cancellation are unit tested; the browser PDF fixtures exercise ordinary, blank, malformed, column and over-page-limit files, not every real encrypted/font/authentication configuration. Chrome 120, Windows/Linux native shortcuts, live VoiceOver/NVDA and real IME hardware remain unverified.

1. Build, load `dist`, grant a controlled website, and open an HTML page with repeated paragraphs.
