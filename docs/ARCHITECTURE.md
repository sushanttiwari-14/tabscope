# Architecture

## Contexts and flow

MV3 service worker owns records, MiniSearch index and settings; synchronous top-level event registrations survive suspension. Extension-owned UI reused in a Shadow DOM iframe overlay and fallback popup window. Content agent only observes dirty state, manages overlay focus, and highlights; extraction is a locally bundled isolated-world function invoked by worker. No webpage postMessage bridge. Search responses go only to extension-origin documents, never arbitrary content scripts. Shadow DOM isolates styles, not host-page observation of interaction. All extracted data rendered with textContent.

## Permissions and API floor

Chrome 120 minimum: modern MV3 promises, storage.session (102+, 10MB since 112), trusted storage access controls, scripting and CSS Highlight support. APIs checked against official [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting), [storage](https://developer.chrome.com/docs/extensions/reference/api/storage), [commands](https://developer.chrome.com/docs/extensions/reference/api/commands), [permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions) documentation on 2026-11-07.

Required tabs (metadata, not DOM access), scripting (execute local code), storage, activeTab (user-invoked overlay). Optional http://*/* and https://*/* requested only from Settings user gesture. activeTab alone cannot automatically read other tabs. No permissions named windows/commands/permissions; these namespaces do not require such declarations. Extension UI is a web-accessible iframe resource; privileged messages require exact extension document URL and runtime ID. Content dirty messages require own extension ID, top frame, tab identity, and matching URL. Content cannot request search/settings/navigation. Permission grants can be partial; contains checked per URL. Revocation purges bodies. Incognito not_allowed.

## Lifecycle and persistence

Version 3 records in storage.session (trusted contexts only), preferences in storage.local (trusted contexts only). Version 1/2 bodies are safely invalidated on upgrade. Activation timestamps are stored only for open session tab IDs; removed tabs are pruned. Session records survive worker suspension, disappear on browser restart/extension reload, so tab IDs never cross browser sessions. Reconcile tab ID and exact URL on recovery and before searches. Navigation immediately increments per-tab generation and removes records through serialized operations. Each extraction checks generation, current URL, permission, exclusion and paused state before commit. Serialized writes prevent stale persistence races. Interactive requests take priority over queued extraction work; one in-progress bounded extraction completes first. Origin permission checks are deduplicated per reconciliation. Dirty observer is debounced 1500ms and throttled to 5s; extraction concurrency one; no DOM extraction on query. Queries reconcile metadata only. SPA routes trigger onUpdated plus dirty URL checks. No content data logs.

Whole-body cap 60k UTF-16 units/tab (roughly 120KB), 20k text nodes; aggregate 2M units (~4MB) leaves room under session quota. Oldest bodies lose text when over budget. MiniSearch adds in-memory overhead; benchmark is observational. A page can use more CPU for computed style; extraction deliberately bounded. No full scans on each mutation: observer sends dirty only, scans after debounce. Search index updated only for changed/removed records, rebuilt once from persisted records on recovery; never scans DOM on typing. Immutable original-source word spans are computed on text updates and reused for snippet selection; this trades extra bounded in-memory token/offset storage for lower warm-query latency. MiniSearch chosen for AND/prefix/field weighting and small locally bundled implementation; no remote executable code.

## Message contracts

UI requests are restricted to exact extension-origin palette.html/overlay.html documents and runtime ID. Search accepts a <=500-unit query and validated session filters; navigation also carries the result URL, content-change timestamp and selected passage ID and recomputes evidence from the worker-owned index. Recovery accepts a tab ID, exact URL and enumerated action (retry/load/include). No client-supplied page text is trusted or returned to content-script callers. Save/clear/revocation/navigation synchronously invalidate extraction generations before serialized work commits. Dirty messages require own extension ID, top frame, tab identity and exact sender URL. Invalid shapes/senders receive an error; no webpage postMessage bridge exists. Page text is rendered with textContent.

The coverage response contains bounded UI details about open tabs and reasons; the renderer displays at most 100 recovery rows, with narrowing guidance. Window/domain filters also scope coverage, while Page text leaves missing bodies visible so their recovery remains understandable. Search applies all filters before result limits and typo fallback. Permission checks always consult Chrome's current state.

## Navigation and fallback

Activate window then tab independently of highlighting. URL and extraction timestamp are revalidated; the content agent independently checks destination URL. Extraction and navigation share the same bounded DOM collector and per-character mapping to original text nodes. Paragraph breaks are recorded separately without assuming folded Unicode offsets equal source offsets. Each passage carries revision, original offsets/ranges, exact quote and 64-unit surrounding evidence. Relocation compares quotes and context before using offset distance; it never unconditionally picks the first identical string. CSS Highlight ranges underline only matched words; nested scrollers are centered before viewport adjustment. No page HTML is replaced. No unrelated word fallback is used. Failed location produces a seven-second dismissible role=status notice on the destination, without opening an overlay. If injection is prohibited, an eight-second action badge/title supplies reachable feedback. Closed tabs still return a source error.

Invocation has a random ID and latest-invocation serial. The actual modal acknowledges readiness after initialization/animation-frame focus. Worker validates extension document, invocation, tab, URL and current top document ID from executeScript; only then marks the content agent ready. Reinvocation shares a loading frame's invocation or refocuses its previously acknowledged singleton, preserving query. Injection, open reply and readiness waits are bounded (1.8 seconds each); failure removes the partial host before falling back. Late readiness is ignored. Fallback creation is single-flight, reuses a tracked popup, and discovers existing palette popups after worker restart. Source browser window is retained in the extension document URL for This window filtering. Reusing a fallback updates a session-only popup/source-window association without resetting the query; this association survives worker suspension and clear-data operations. Unchanged extraction retains the content-change timestamp while separately updating its indexing time. Host pages can still remove/obscure the overlay after acknowledgment; this is not continuous visibility monitoring.

## Shortcut defaults

Chrome’s [commands documentation](https://developer.chrome.com/docs/extensions/reference/api/commands) permits Space and requires `MacCtrl` to represent physical Control on macOS (`Ctrl` otherwise maps to Command). The Mac suggestion is `MacCtrl+Space`; Windows/default is `Ctrl+Shift+Space`. No global scope. Existing preferences must be changed in chrome://extensions/shortcuts, not through an API. Settings reads commands.getAll to show the actual assignment. OS shortcuts take priority. [Apple](https://support.apple.com/en-us/102650) documents Control+Space as an input-source shortcut; [Microsoft](https://support.microsoft.com/en-au/accessibility/windows/keyboard-shortcuts-in-windows) documents Ctrl+Space as a Chinese IME toggle. Windows uses the extra Shift modifier to avoid that specific toggle; compatibility is still subject to the user’s OS/apps/extensions.

## Transparent overlay shell

Supported pages load overlay.html inside the isolated iframe; its root/body are statically transparent and use normal color-scheme, matching the iframe element. Semantic theme tokens still control palette colors. palette.html remains the standalone fallback/options shell. The worker accepts privileged UI messages only from these two exact extension document URLs. The fixed host applies token-derived 35% black dimming and 6px backdrop blur; inline host styles survive site style-src restrictions. No page navigation, new tab, or OS-wide window is used for a supported page.

## Multi-passage and query pipeline (2026-11-09)

MiniSearch remains the candidate index. Parsed query components are ANDed, with exact/prefix candidates plus at most eight conservative approximate expansions per eligible bare lowercase English word. Vocabulary work is bounded to 500 eligible tabs, 2M units and 12,000 words. Source evidence validates quoted phrases separately in title, URL and body; source gaps preserve literal punctuation and normalize whitespace; phrases stay inside paragraph/page/column boundaries. Context-sensitive scripts also use mapped canonical source-sequence verification. Exact/prefix tabs are sorted ahead of all approximate tabs; within a group the weakest component quality tier sorts first, then field-weighted MiniSearch relevance, component quality and passage completeness contribute, then recency/id break ties. Body passages score distinct covered components (100 each), best match quality (canonical 5, relaxed 4, prefix 3, variant 2, typo 1) each actually covered explicit phrase (10), with an inverse source-span proximity tie-breaker. Strong complete body evidence beats weak fuzzy-only evidence. At most 2,000 occurrences per component and 2,000 context candidates/tab feed passage generation; overlapping windows merge only inside the same paragraph and under 240 source units. Retain the best 32, then restore document order; select the best by score. Capped flags indicate limited passage coverage. Identical quotes at different offsets remain different identities.

Up to 100 tab groups and 32 passages/group bound response size. Eight recent query/filter results are cached in memory; any record/coverage/recency change invalidates them. Benchmarks explicitly disable this cache. UI request sequence IDs reject obsolete responses and composition start invalidates in-flight responses. Passage selections survive polling by source ID; a query change deliberately resets them. Shared controls are outside the listbox options. No global browser/OS command is added. Native Tab reaches Previous/Next and Up/Down retain tab selection. On the destination page, unmodified Left/Right arrows operate its open passage navigator; editable fields, native controls, composition and modified chords remain native.

## Local PDF extraction

Chrome's built-in reader encapsulates its text inside a privileged viewer; content scripts cannot inspect that text. See [Chromium's explanation](https://groups.google.com/a/chromium.org/g/chromium-extensions/c/CNPumQ7X4qs). A separate extension-owned offscreen document uses locally bundled PDF.js compatibility build and a local module worker, following the [offscreen lifecycle API](https://developer.chrome.com/docs/extensions/reference/api/offscreen) and [PDF.js document/page API](https://mozilla.github.io/pdf.js/examples/). The `offscreen` permission enables workers, not additional website access. Parser/worker files are not web-accessible resources. CSP stays script-src self, evaluation is disabled, and no remote worker/font/parser is introduced.

Suffix/document evidence or a three-second HEAD probe identifies a candidate; the offscreen GET refuses redirects and attachment responses, verifies MIME and PDF signature, streams under 12 MiB, and releases binaries after parsing. Only one queued parser runs, with a 20s abort/destroy deadline, 40 pages, 60k text units, and 20k items/page. Ordinary search/HTML indexing are not serialized behind parsing; per-page commits enter the existing urgent queue and revalidate job token, generation, URL, loaded tab, pause/exclusion and permission. Cancellation destroys fetch/parser on tab navigation/closure, clear, exclusion or permission removal. Unknown old tokens are rejected after suspension; initialization closes orphan offscreen work, labels interrupted partial coverage, and refresh can restart it.

Persisted PDF records contain source URL, fingerprint, physical pages/labels, page-local mapping and status, with page separators and column boundaries. Ligatures and soft hyphens normalize during PDF extraction; short line-end hyphenation is joined only with same-column geometry evidence. Headers/footers are retained rather than guessed away. Large/reversed column jumps break phrases. This conservative order can miss phrases in complex documents. No OCR, custom reader or access-control bypass exists. Native PDF navigation commits `page=N` preserving other fragment/query bytes and replacing conflicting named-destination parameters, then reloads the same tab; tests inspect the real reader page selector, not just the address bar. Text highlighting is never reported for PDF pages. Reloading may reset unsaved reader annotations.

Paragraph offsets and PDF page maps also count against the aggregate session body budget, so dense location metadata can reduce retained text below the 2M-unit text ceiling. Eviction clears both text and location maps and remains labeled in coverage.

Destination navigation now flattens validated, deduplicated source ranges from the returned passages into document-order individual matches (at most 2,048). The initial match belongs to the selected palette passage. The destination labels these as Match N of M; palette previews continue to count passages. Highlighting has no expiry timer. An outside page pointer/click clears both the highlight and navigator without consuming the underlying click; navigator clicks preserve the active session. Bare Left/Right keys then return to native page behavior until another result is opened.

## Updating an existing page agent

Builds derive a content-agent version from its source/dependencies. Reinjection reuses the same version, while an older versioned controller is disposed (runtime listener, DOM listeners, observer, timer, overlay and highlight) before replacement. Legacy boolean-only controllers are not allowed to suppress initialization. Destination messages use a new protocol and independent highlight/style/navigator names so a former controller's delayed cleanup cannot erase the new session. A navigation session caches the source-to-DOM mapping between real page mutations; arrow keys do not run a full extraction on an unchanged page. Equivalent replaced text nodes trigger one queued relocation, canceled if the user dismisses the session.

## Shared multilingual analysis (2026-11-12)

`analysis.ts` owns NFC/case forms, explicit relaxed aliases, cached Intl segmentation, original-offset tokens and source projections. `distance.ts` removes the search/matching cycle. Content and palette bundles no longer import the search engine. Analyses for body/title/URL and source-sequence grapheme maps are cached on content updates; URLs disable prose aliases/approximation. Supplemental verified candidates handle aliases, Turkish casing and context-sensitive scripts without n-gram relevance or arbitrary exact-candidate caps. Approximation requires an en hint; missing/invalid hints do not enable English stemming. The existing approximate vocabulary cap remains documented separately from exact verification. Evidence ranges drive title, passage and URL-excerpt ink; visual ellipses never enter source offsets.

Session schema 3 accepts optional validated locale hints; `analysisVersion` is policy 1. Every worker initialization rebuilds all derived indices/maps with the current policy from reconciled session source records; query keys include the policy and sync invalidates locale changes. No derived index is persisted. Agent version hashing includes the shared analysis and localization helpers. Memory measurements include all token forms and projection maps. See [MULTILINGUAL.md](MULTILINGUAL.md) for normalization details, the support matrix and compatibility fallback.

PDF localization is resolved in the background worker with Chrome i18n and passed as a bounded whitelist of templates to the authenticated offscreen message handler. Offscreen documents expose only runtime, so they never call unavailable i18n APIs or ship untranslated status keys. Startup recovery checks offscreen contexts with the Chrome-116+ runtime.getContexts API, preserving the Chrome 120 floor.
